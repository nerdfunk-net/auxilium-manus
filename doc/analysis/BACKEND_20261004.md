## 0. Verdict in one paragraph

The three areas are in good mechanical shape (ruff clean on all 247 changed files, four guard scripts OK,
**4 175 tests passing at 86.35 %** coverage vs. 2 945 / 83.4 % at the last audit) and the Catalyst Center
integration is the best-hardened HTTP integration in the codebase: it applies the outbound-URL policy at
create, update **and** on every request, validates every controller-issued id before it enters a path,
bounds filters, paging and polling, never follows redirects, retries only 429, sanitises errors, and sits at
95–99 % coverage. The five "before publish" items of the last audit (SM1–SM4, B1, B2) are **fixed and
verified** (§2). The AI-collaboration feature has a well-thought-out consent model (strict ownership,
time-boxed, expire-all-on-disable, kill-switch account, refuse-on-reference-drift, pre-run gate).

What is wrong is concentrated in three places:

* **ISE hands TACACS+ shared secrets to the read-only role (ISE1, H).** `GET /sources/ise/{id}/devices/{device_id}`
  and `/devices/name/{name}` return the raw ERS `NetworkDevice`, including `tacacsSettings.sharedSecret`, to anyone
  with `sources.ise:read` — which the seeded `viewer` role holds. The whole sealed-secret design (workflow context,
  `credentials:reveal`, the secret manager) is bypassed by one GET. A second leak of the same class: a literal
  `new_key` typed into `add-to-ise` / `update-ise-tacacs-key` is stored in the workflow definition and pushed to
  git in cleartext (ISE2, the SM3 problem re-introduced for the ISE steps).
* **The AI feature's authorization lives in a CLI script, not in the service (AI2), and AI edits flow
  unattended into schedules (AI1).** `update_workflow_for_ai_session` / `update_notes_for_ai_session` skip the
  ownership check on the caller's say-so, the script that is supposed to check consent has no test, and a
  scheduled workflow executes whatever canvas the AI last wrote. `ai_template_apply.py` is weaker still: no
  per-item consent, any template can be overwritten (AI3).
* **The credential-binding and transport rules fixed for the Secret Manager were not applied to the other
  sources (CC1, CC2).** Any global credential — including a device SSH password — can be bound to an ISE /
  Catalyst Center / Nautobot source whose URL the `sources.*:write` holder chooses, and `/test-connection`
  then sends it there as HTTP Basic; `verify_ssl=false` and plain `http://` are honoured in production.

Beyond that: the project-wide `pyright` run is red (159 errors, **X2**), the local virtualenv is out of
sync with `requirements*.txt` (`pip-audit` of it reports 27 advisories; a fresh install resolves to fixed
versions — **X1**, corrected 2026-10-04),
about 110 lines of Catalyst Center code are only reachable from tests (CC3), and the source CRUD / HTTP-client /
step-helper boilerplate is copy-pasted again rather than shared (§10).

None of the **M**/**H** items is exploitable without an authenticated user; ISE1 needs nothing beyond the
built-in `viewer` role.

### 3.1 What is done well

- **The consent model is real, not decorative.** Enabling is owner-only (`creator_id == user_id`, deliberately
  stricter than the visibility rules), time-boxed (1 min – 24 h), `disable` expires **every** active row (not
  just the newest — the repository comment explains the overlapping-rows case), rows are kept as an audit trail,
  and the `ai-assistant` account is seeded **inactive** with a random discarded password so the admin switch is
  a genuine kill-switch.
- **The AI never gets a login or an HTTP surface.** There is no AI-reachable router; all writes go through two
  scripts that require the account to be active.
- **Refuse-on-drift** (`ai_workflow_apply.py:150-158`) turns "resolve live or fail loudly" into code, and the
  validation result is returned in full so the caller sees Tier 1/3/4 findings.
- **The pre-run gate is a good second layer.** `RunService._assert_no_blocking_validation_errors` blocks Tier 1–3
  errors on every dispatch path, creating no run row; the scheduled path mirrors it and records a visible failed run.
- **Validation reuses the runtime rules** (`effective_produces`, `StepCapabilitySpec`, `graph_resolution`) instead of
  re-implementing them, validates credentials by **metadata only** (never decrypts), and the Tier 4 warnings are
  explicitly advisory.
- `AI_ASSISTANT_PERMISSIONS` is a curated allow-list (no `workflows:execute/delete`, `credentials:reveal`, or
  anything under `rbac.* / users / system.* / secret_manager.*`), and a unit test pins it.
- Test coverage of the session service/repository and the validation service is 95–98 %.

### 4.1 What is done well

- **Outbound policy at every layer.** `validate_outbound_http_url(resolve_dns=True)` on create, on update, on
  inline test, and again in `_validated_base` before **every** request (off the event loop via
  `validate_outbound_http_url_async`), so a row that predates the check or a DNS change is still caught.
- **Path-injection discipline.** Every controller-issued id (device, task, file, site) goes through
  `safe_device_id` (`^[A-Za-z0-9_-]{1,64}$`) before it enters a path; `find_by_ip` parses with `ipaddress`.
- **Bounded everything:** ≤ 50 values per filter (and 255 chars, no control characters), `_MAX_PAGES = 200`, ≤ 5
  commands per request (split sequentially), ≤ 20 devices per request, ≤ 3 parallel requests, 150 polls ×
  2 s, step timeout ≤ 300 s, 429 retried at most 3× with `Retry-After`/backoff capped at 30 s.
- **No redirects followed** (httpx default), errors sanitised (`_error_message` truncates to 300 chars, the 5xx paths
  use `raise_internal_server_error(status_code=502)`), the password only appears in the Basic header and the SHA-256
  token-cache key, and `verify_ssl=False` is logged at WARNING with the host.
- **Read-only by construction:** the service exposes no write path (the controller enforces `show`-class).
- **Shared step helpers** (`catalyst_center_targets`) give every step the same source-grouping, per-source credential
  resolution before any I/O, and failure shape; partial failures are per-device, controller failures per-chunk.
- **Layering and lifecycle:** model → service → router, service built through `service_factory`, `CatalystCenterService`
  started/stopped in **both** `main.py` and `hatchet/worker_services.py`, `ValueError`/`RuntimeError` usage per the
  step rules, registry + UI entries present for all six steps.

### 4.2 Findings

| # | Sev | Finding | Location | Fix |
|---|---|---|---|---|
| CC1 | **M** | **Any global credential — including a device SSH password — can be bound to a source and sent to a URL the `sources.*:write` holder chooses.** `assert_global_credential` → `CredentialManager.source_credential` (`manager.py:119`) checks `visibility == "global"` and nothing else: no type check. `create_source`/`update_source` and `POST /sources/catalyst_center/test-connection` (inline `{url, credential_id}`) accept it; `validate_outbound_http_url` blocks link-local/metadata/loopback but **allows any public host and plain `http://`**. `test-connection` then sends `credentials.username:password` as HTTP Basic to `<url>/dna/system/api/v1/auth/token`. ### 5.1 What is done well

- **Secrets in the workflow path are handled correctly.** `add-to-ise` seals the key (`seal_secret`) before it touches
  an attribute bag, records the create request through `append_request_record` (marker-based redaction, so the
  stored request shows the sealed marker, not the key), and keeps the request/response in `DeviceContext.requests`,
  which is display-only and unreadable by `{path}` expressions. `get-ise-tacacs-key` seals what it reads.
- **`DeviceGroupEnsurer`** walks `#`-paths from the root, creates only missing levels, refuses to guess a malformed
  root, remembers verified paths per run, and treats "already exists" after a race as success.
- **Outcome design for `add-to-ise`** (`success` / `exists` / `failure`, per-device failure vs whole-step
  `failure` on connectivity loss, pre-flight `test_connection()`) is clear and documented.
- The ISE client applies the outbound policy per request, never logs the password, and `update_device` documents the
  ERS "PUT replaces the whole object" trap and merges first.
- Executors at 93–96 % coverage.

## 12. Python best-practice notes

- **Good:** frozen dataclasses for parsed config and results (`_ParsedConfig`, `_ResolvedFields`, `CatalystCenterCredentials`),
  `from __future__ import annotations` everywhere, `TYPE_CHECKING` imports for the session pool, `ValueError`/`RuntimeError`
  split, small pure helpers (`_parse_netmask_override`, `_extract_ip_mask`), contextvar-bound run-event context, `Self`
  and `Literal` used where they help, `frozenset` constants, no mutable defaults, no `datetime.utcnow`, no `time.sleep`
  in async code (the two `time.sleep` calls are in the thread-based repo lock and netmiko retry).
- **PEP 758:** `except TypeError, ValueError:` (`coerce.py:24`) is legal only on 3.14; fine given `pythonVersion = "3.14"`,
  but it blinds older analysers (bandit 1.9.4 skipped the file).
- **Broad `except Exception` is the dominant pattern in executors** (201 in changed files). Most re-raise as `RuntimeError`
  or convert to a per-device failure, which is intentional; the two to review are `store_in_db.execute` (turns any
  exception, including programming errors, into a per-device failure with `type(exc).__name__.lower()` as the code) and
  `ai_*_apply.main` (prints raw text).
- **Typing:** the biggest single gap is the Nautobot service protocol (X2). `dict[str, Any]` is used at several service
  boundaries where a `TypedDict` or frozen dataclass would give the checker something to hold (ISE responses, Catalyst
  payloads before `normalize_device`).
- **Boolean flags parsed by hand ten times** (`_parse_bool`) — a shared `parse_bool(config, key, default)` already exists in
  two places.
